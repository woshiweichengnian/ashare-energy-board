# Phase 0：数据源实测与运行时可行性探针

## Goal

项目目前没有经过实测的行情源：成交额单位、`399001.SZ` 成交额口径、批量能力、分时历史深度、安全轮询频率，以及 Electron 下是否能用零 MSVC 的 SQLite，都还是假设。

完成后，后续阶段可以直接按 `docs/DATA_SOURCES.md` 实现适配器、调度器和持久层，不需要再猜测上游行为。

## Behavior

- `node scripts/spike-data-sources.mjs` 可在真实网络下重复运行，对候选公开源（东方财富 `push2`/`push2his` trends2、腾讯 `qt.gtimg.cn` 及分时接口、新浪 `hq.sinajs.cn`）逐一探测，并在终端打印结构化结果。
- 每个候选源需报告：
  - 能否**单次批量请求**取得 `000001.SH`、`399106.SZ`、`399001.SZ`、`399006.SZ`、`000688.SH`、`600519.SH`、`300750.SZ` 的实时快照（最新价、涨跌幅、成交量、成交额）。
  - 能否取得**今日 + 上一交易日**完整 1 分钟分时（价格、成交额）序列，以及缺失分钟、午休、`09:25`、`15:00` 在返回数据中的表现。
  - 成交额原始单位（元 / 万元 / 其他）及换算到人民币元的系数。
  - `399001.SZ` 与 `399106.SZ` 成交额对比，判定 `399001.SZ` 是 `成分股` 还是 `深市全市场` 口径。
  - 3 秒与 5 秒间隔下各一轮有界压测（每轮约 20 次批量请求）的延迟分布、失败/403/429/空包次数。
- 能解析到同花顺 API Key 时，只做最小探测：交易日历 1 次、标的搜索 1 次、指数快照 1 次，记录真实字段、`code` 信封与延迟；解析不到时输出“未配置，待验证”，脚本不失败。
- 验证目标 Electron 版本内嵌 Node 是否可直接使用 `node:sqlite`（建表、写入、读取）；不可用或不稳定时，验证 `sql.js`（WASM）或其他预编译方案并定型。
- 将全部结论写入 `docs/DATA_SOURCES.md`。

## Constraints

- 同花顺 Key 解析顺序：`HITHINK_FINANCE_API_KEY` → `%APPDATA%\hithink-finance\credentials.env`（此阶段尚无 `safeStorage` 存储）。
- Key 只能放在 `X-api-key` 请求头；不得出现在 URL、终端输出、报告或 Git 中。
- 所有请求必须有界（固定次数、带超时），不得做无限循环或高并发压测。
- 宿主环境：Windows、Node 26、无 MSVC；探针及其依赖不得触发 `node-gyp` 编译。
- 同花顺端点与成功判定以 `docs/PLAN.md` §2.4 为准。

## Out of Scope

- 正式的 `MarketDataProvider` 适配器、调度器或任何 `src/` 业务代码。
- 正式的 Electron 工程脚手架（验证 `node:sqlite` 可用临时最小 Electron 进程，验证后不保留为工程结构）。
- 对同花顺做压测或高频调用。

## Acceptance Criteria

- `scripts/spike-data-sources.mjs` 在本机可运行完成，单个候选源失败不会中断其余探测。
- `docs/DATA_SOURCES.md` 包含：
  - 主公开源、备用公开源及优先级，每个源的精确 URL、参数、响应字段到“价格/涨跌幅/成交量/成交额/时间”的映射。
  - 每个源的成交额单位与换算系数。
  - 四大指数各自的成交额口径结论（`全市场` / `成分股`），含 `399001.SZ` 的实测数据依据。
  - 2 日 1 分钟分时的可得性与边界分钟表现。
  - 推荐默认轮询间隔及依据（压测数据）。
  - 同花顺三个端点的实测字段与延迟，或明确标注“未配置，待验证”。
  - 定型的零 MSVC SQLite 方案及验证所用 Electron 版本。
- 脚本输出、报告与仓库中搜索不到 API Key 明文。
