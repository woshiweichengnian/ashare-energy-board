# Phase 3：混合双源采集与自适应调度

## Goal

核心引擎已能计算，但还没有真实数据输入：主进程不会拉取行情、补齐分时、落盘，也不会在故障或非交易时段调整行为。

完成后，主进程在任意时刻启动都能自动准备好“今日 + 上一交易日”数据，盘中按安全频率批量刷新全部监控标的、实时计算能量与告警，并通过 IPC 向渲染进程推送状态；非交易时段自动停止高频轮询。

## Behavior

**数据适配**
- 按 `docs/DATA_SOURCES.md` 接入主公开源、备用公开源和同花顺，提供批量快照、2 日 1 分钟分时、标的搜索、健康检查能力。
- 所有成交额在适配器边界统一换算为人民币元。

**启动与补齐**
- 启动时加载交易日历（SQLite 缓存当日有效则直接用，否则从同花顺拉取近一年并缓存），确定 `today` 与 `prevTradingDate`。
- 同花顺 Key 未配置或日历拉取失败时：使用已缓存日历；无缓存时以公开源 2 日分时推断上一交易日，并将日历状态标记为降级。
- SQLite 中缺少昨日完整 240 分钟或今日已过分钟时，从公开源一次性补齐并落盘。

**盘中轮询**
- 交易时段按配置周期（默认取 `DATA_SOURCES.md` 推荐值，可调 3–15 秒）以最少请求数批量拉取 5 个指数 + 全部自选股。
- 每次刷新后更新内存态，调用核心引擎计算能量状态与告警事件，并通过 IPC 推送给渲染进程；告警事件交给告警派发入口（Phase 4 接通渠道）。
- 每分钟闭合时将该分钟写入 `intraday_bars`；`09:25–09:26` 捕获开盘竞价并写入 `auction_snapshots`。
- 自选股增删后无需重启即纳入下一轮轮询。
- 收盘后触发一次 30 交易日清理。

**故障与退避**
- 连续错误或 HTTP 429/403 时轮询间隔翻倍（3s → 6s → 12s，有上限）并切换到备用源；恢复后逐步回到配置间隔。
- 所有公开源失效时，用同花顺低频快照兜底；遇到 `code=4001` 严格退避，最多重试 3 次。
- 上游缺分钟或数据过期时标记 `stale` / `degraded`，不补 0、不生成合成数据。

**非交易时段**
- 午休、盘后、非交易日停止高频轮询，进入复盘模式：推送最近交易日完整曲线与能量结果。

**状态暴露**
- IPC 状态中包含：当前数据源、最近更新时间、请求延迟、当前轮询间隔、`stale` / `degraded` 标记、日历来源。

## Constraints

- 网络请求、持久化、调度全部在 `src/main/`；计算只调用 `src/core/`，不在主进程重写公式。
- 同花顺不得进入秒级轮询循环。
- IPC 消息使用 `src/shared/` 中的类型化契约。
- Key 只出现在同花顺请求头中。

## Out of Scope

- 通知、提示音、托盘、HUD 等展示与告警通道（Phase 4/5）。
- 自选股管理 UI（此阶段直接读 `watchlist` 表）。
- 回放模式（Phase 6）。
- 通用重试 / 熔断框架。

## Acceptance Criteria

- 各适配器的响应解析与单位换算有基于真实样本的单元测试并通过。
- 模拟 10:35 启动：自动补齐当日 `09:30–10:35` 与昨日全天 240 分钟，并开始轮询。
- 盘后或非交易日启动：推送最近交易日复盘数据，且无高频轮询请求发出。
- 主源故障注入：自动切到备用源，IPC 状态中的数据源与延迟随之变化；主源恢复后间隔回落。
- 上游缺分钟时 `intraday_bars` 中不出现补 0 的分钟，状态带降级标记。
- 未配置同花顺 Key 时应用仍可基于公开源运行，日历状态显示降级。
- `npm run typecheck`、`npm run test` 通过。
