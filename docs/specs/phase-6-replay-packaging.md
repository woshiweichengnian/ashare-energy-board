# Phase 6：全天回放验证与 Windows 便携版打包

## Goal

各模块已单独验证，但还没有一次端到端地跑通完整交易日，也没有可交付的安装物。

完成后，开发者可以用已录制的真实交易日数据回放 09:25 → 15:00 全流程以验证计算、告警和界面，并得到一个可在任意目录双击运行的 Windows 便携版 `.exe`。

## Behavior

**回放模式**
- 通过开发态启动参数（如 `--replay <交易日>`）或测试脚本，从本地 SQLite 已录制的真实分钟数据中选择一个交易日回放。
- 回放按时间顺序推进 09:25 → 15:00，经过与实盘相同的聚合、能量计算与告警判定，并驱动 HUD 与详情浮层渲染；支持加速播放。
- 回放期间界面明确标识“回放”及回放日期，不发起实时轮询。
- 回放产生的告警在界面中可见并标记为回放，不写入实盘 `alert_events`、不弹 Windows 通知。
- 所选交易日或其上一交易日数据不完整时，回放照常进行并显示降级，不补造数据。

**质量门禁与打包**
- `npm run typecheck`、`npm run test`、`npm run build` 依次通过。
- `npm run package` 生成 Windows 便携版 `.exe` 到 `release/`。
- 便携版运行时数据（数据库、设置、加密 Key）写入用户数据目录，不依赖源码目录，也不写回打包产物所在目录之外的工作区。

## Constraints

- 回放复用实盘计算路径，不另写一套计算逻辑。
- 回放数据只能来自真实录制数据，不使用合成行情。
- 打包产物与仓库中不得包含 API Key、`.env`、开发数据库或临时数据。
- 零 MSVC：打包过程不触发本地 C++ 编译。

## Out of Scope

- 安装版（NSIS / MSI）、自动更新、代码签名。
- 非 Windows 平台打包。
- 在线下载历史分钟数据用于回放（只用本地已录制数据）。

## Acceptance Criteria

- 选择一个本地已录制的完整交易日回放：全天无报错跑完；`MARKET_TOTAL` 等于 `000001.SH + 399106.SZ`；跨午休斜率连续；`09:30–09:34` 无告警；产生的快速放/缩量告警与按同样参数离线计算的结果一致；界面全程标识为回放。
- 类型检查 0 错误，单元测试全部通过，`npm run build` 成功。
- `release/` 下产出便携版 `.exe`；将其复制到一个不含源码的新目录双击运行：托盘、悬浮窗出现，数据正常刷新（或非交易时段显示复盘），修改的设置重启后保留。
- 仓库工作区与 `release/` 产物中搜索不到 API Key 明文、`.env` 文件或开发数据库文件。
